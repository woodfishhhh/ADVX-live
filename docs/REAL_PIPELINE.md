# 真实管线联调

桌面端已通过 Electron Main 与本地 FastAPI 后端连接。Renderer 不持有本地后端令牌、模型密钥或 StepFun 密钥；它只通过受限 IPC 提交采集结果。

## 准备

需要以下可用凭据：

- 一个 OpenAI-compatible 多模态模型的服务地址、模型名称和 API Key。
- 可选：一个 StepFun API Key，用于 `stepaudio-2.5-asr` 实时语音识别。

不开启麦克风也可以开播。启用语音后，麦克风音频会发送给 StepFun；最终转写会与近期画面、文字上下文一起交给多模态模型。

## 启动

首次准备依赖：

```bash
pnpm install
uv sync --project apps/backend --group dev
pnpm contracts
```

从仓库根目录启动完整开发环境：

```bash
pnpm dev
```

这个命令会先启动后端并等待健康检查通过，再打开桌面端：

- 动态分配的回环端口上的 FastAPI 后端，实际地址会打印在终端中。
- Electron 桌面应用。
- 两个进程共享的单次启动本地令牌。

不要分别运行 `pnpm dev:backend` 和 `pnpm dev:desktop` 进行真实联调；分别启动时必须自行给两个进程传入完全相同的 `ADVX_LOCAL_TOKEN`。

## 首次配置

1. 打开桌面端“设置”。
2. 填写模型服务地址、模型名称和模型 API Key；需要语音识别时再填写 StepFun ASR API Key。
3. 点击“保存连接”，等待“已安全保存并接入后端”的提示。
4. 回到“直播控制台”，确认底部显示“后端 · 已连接”。

密钥由 Electron `safeStorage` 加密保存。操作系统不提供安全存储时，配置只对本次运行生效，密钥不会明文落盘。

同一后端进程不会热切换 Provider。若保存了与当前运行不同的配置，界面会提示重启；退出并重新执行 `pnpm dev` 后，桌面端会加载已加密配置并注入新后端。

## 端到端验证

1. 选择屏幕或窗口；摄像头和麦克风均可选。
2. 点击“开始直播”。
3. 等待状态变为“直播中”，并确认“图像适配器 · 已就绪”。
4. 可在输入框发送文字；配置 ASR 后也可以开启麦克风说话。
5. 观察“房间互动”和 Overlay 中出现由后端生成的 AI 弹幕。
6. 测试暂停、恢复和结束直播，确认采集设备随 Session 状态释放和恢复。

运行时数据路径如下：

```text
麦克风 -> 16 kHz 单声道 PCM -> StepFun ASR -> 最终转写
屏幕/摄像头 -> 每 500 ms JPEG 帧 -> 后端 5 秒窗口
文字输入 ---------------------------------------> 房间上下文
7-15 帧 + 房间上下文 -> OpenAI-compatible 多模态模型
模型结果 -> 弹幕校验 -> 桌面端与 Overlay
```

音频约每 2 秒提交一个片段。前端每完成一张压缩图就立即发送，不再整理或丢弃代表帧；后端每 5 秒检查一次新增帧，满 7 张才调度，并在单次模型请求中按时间顺序携带最多 15 张。

## 常见问题

- “正在启动本地服务”：这是正常启动状态，健康检查通过后会自动消失。
- “本地服务启动失败”：点击“重试”；若仍失败，检查终端中的后端文件、Python 环境或端口错误。
- “本地服务连接中断”：桌面端正在自动恢复，恢复前新的音频和画面不会发往后端。
- “等待配置”：模型地址、名称或 API Key 尚未成功注入后端，回到设置页重新保存。
- 保存后提示重启：当前进程已有另一组 Provider 配置，这是预期保护行为。
- 没有语音回应：确认 StepFun Key 可用、麦克风有输入，并查看启动终端中的 ASR 请求错误。
- 画面状态长期等待后端：确认 Session 仍为“直播中”，并查看终端是否出现 ingest 拒绝或 WebSocket 断开。
- “后端失败”：模型调用或实时连接失败，直播会停止并显示可操作的配置检查提示。
- macOS 无法采集：在“系统设置 -> 隐私与安全性”中允许麦克风、摄像头和屏幕录制权限，然后重启应用。
